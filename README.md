# RBY1 人手示教 → 机器人回放轨迹（真机部署包）

这个仓库里是 RBY1-A（v1.2）**左臂**的回放轨迹，由头部相机录制的人手示教转换而来，已经在 MuJoCo 物理仿真中逐个回放验证过。当前包含三个任务：

| 任务 | 内容 | 可用 episode |
|---|---|---|
| `swap_v1` | 一根手指穿过刷子的环形手柄，捏住环管把刷子拿起来 | ep0–7（8/8） |
| `cup_v1` | 捏住杯沿（一指在杯内、一指在杯外），把杯子拿起来 | ep0、1、2、3、7、8、9（7/10） |
| `box_v1` | 夹爪闭合，用指尖推纸箱的左侧面，把纸箱往中间推 17–23 cm | ep0、1、2（3/3） |

被拒的 episode（cup_v1 ep4–6）和原因见 [REJECTED_EPISODES.md](REJECTED_EPISODES.md)。

所有轨迹都是**0.5 倍速**版本，日期 2026-11-26。

## 2. 关节轨迹文件格式（`trajectories/joint/*_joint.csv`）

每一行是一个采样点，列如下：

| 列 | 单位 | 说明 |
|---|---|---|
| `time_s` | s | 采样时刻，从 0 开始。swap_v1 / cup_v1 **间隔不均匀**（133–382 ms），因为各段做了不同程度的时间缩放；box_v1 间隔均匀（133 ms）。执行时按这个时间轴的真实时间走 |
| `phase` | — | 抓取任务（swap_v1、cup_v1）：`approach`（从初始姿态接近）→ `insert`（夹爪插入）→ `dwell`（停留）→ `close`（闭合，手臂不动）→ `transport`（抬起 / 搬运）。<br>推箱子（box_v1）：`approach` → `contact`（贴到箱子侧面）→ `dwell`（停留）→ `push`（推）→ `hold`（停住）→ `retreat`（后退 6 cm、抬高 8 cm）→ `final_hold`（静止） |
| `left_arm_joint_1..7` | rad | 左臂 7 个关节，名字和机器人 `joint_state` 一致（对应 URDF `left_arm_0..6`） |
| `right_arm_joint_1..7`、`torso_joint_1..6`、`head_joint_1..2` | rad | **全程固定不变**：右臂 = 新初始姿态，躯干 / 头部 = 录制时的值 |
| `left_gripper_finger_joint_1` | m | 夹爪目标，按 `joint_state` 里的定义写（**符号待真机确认**，见第 5 节） |
| `left_gripper_open_m` | m | 每根手指的张开量：0 = 闭合，0.05 = 全开 |
| `left_gripper_closed_norm` | — | 0 = 全开，1 = 闭合 |
| `gripper_closed` | 0/1 | 闭合指令。从第一个 1 开始一直保持闭合，中途不会再张开 |
| `right_gripper_finger_joint_1` | m | 固定 |

## 2b. 关节限位、速度 / 加速度上限、频率，以及和人手视频的时间对应

### 关节位置限位（左臂）

范围取 URDF 和 MuJoCo 模型限位的交集；轨迹另外和这个范围的两端都保持至少 5° 的距离（第 7 节有验证）。

| 关节 | 下限 (rad) | 上限 (rad) |
|---|---|---|
| left_arm_joint_1 | −2.3562 | 2.3562 |
| left_arm_joint_2 | −0.0175 | 3.1416 |
| left_arm_joint_3 | −2.0944 | 2.0944 |
| left_arm_joint_4 | −2.6180 | 0.0100 |
| left_arm_joint_5 | −3.1416 | 3.1416 |
| left_arm_joint_6 | −1.5708 | 1.9199 |
| left_arm_joint_7 | −2.7053 | 2.7053 |

### 速度 / 加速度

| 关节 | URDF 速度上限 (rad/s) | 生成轨迹时用的上限 (rad/s) = URDF × 50% |
|---|---|---|
| 1–4 | 3.1416 | 1.5708 |
| 5–6 | 6.2832 | 3.1416 |
| 7 | 2.0944 | 1.0472 |

- 加速度：URDF 上限是 10 rad/s²，生成时用 5 rad/s²（50%）。
- 仓库里的文件都是 **0.5 倍速**：时间轴在上面的基础上再拉长一倍，所以名义速度不超过 URDF 上限的 25%，名义加速度不超过 12.5%。按 PCHIP 插值后实测：峰值速度 ≤ 25%，峰值加速度 ≤ 44%。插值本身会让加速度出现一些尖峰，所以加速度比名义值高。
- 夹爪手指速度按 URDF 的 0.05 m/s 估算。

### 频率和执行时钟

- swap_v1 / cup_v1 的采样点**不是固定频率**：相邻采样点间隔 133–382 ms，因为每一段的时间缩放不同。box_v1 是固定的 133 ms（7.5 Hz）。
- **执行时请严格按 `time_s` 的真实时间走（1.0 倍）**，不要加速。如果想更快，需要重新生成轨迹并重新检查，不能直接把时间轴压短。
- 建议控制器以 **≥ 100 Hz** 发送插值后的关节指令（PCHIP 或样条，见 `examples/replay_reference.py`）。仿真验证在 15 Hz 的网格上做插值，物理步长是 2 ms。
- 人手示教视频和所有标注都是 **15 Hz**。

### 机器人时间和人手视频的时间对应（`human_frame`、`human_time_s` 列）

**机器人回放的时间轴和人手视频的时间轴不一样**，原因有三：
1. **接近段（`approach`）**：这一段是从新初始姿态规划出来的，不跟随人手，所以没有对应的人手帧，`human_frame = −1`。
2. **插入、停留、闭合段**：对应人手捏住物体前后的那几帧。停留和闭合段的人手帧会重复，因为机器人在这段时间里静止、夹爪在闭合。
3. **搬运段（`transport`）**：按人手动作走，但为了满足速度和加速度上限，每条 episode 都整体放慢了 1.1–2.9 倍，然后再乘 0.5 倍速。
4. **box_v1**：`push` 段按人手推的过程走（0.5 倍速）；`contact`、`dwell`、`hold`、`retreat`、`final_hold` 是规划出来的固定动作，对应的人手帧会重复或停在最后一帧。

为了方便对齐，关节文件和 EE 文件的每一行都附带两列：
- `human_frame`：这个采样点对应的人手视频帧号（15 Hz，−1 表示没有对应帧）；
- `human_time_s`：等于 `human_frame / 15`。

**如果要把真机回放录下来、和人手视频配对**（比如做人手 ↔ 机器人的配对数据）：按 `human_frame` 把真机录到的每一帧映射到对应的人手帧。一帧人手画面会对应多帧机器人画面，因为机器人更慢。

**不要用 `human_time_s` 作为执行时钟**，让机器人按人手的速度运动：那样会超过速度和加速度上限，人手原速下加速度最高达到 URDF 上限的 4 倍。

## 3. 初始姿态 / reset 标准文件（必须先到位）

**标准 reset 文件**：`start_posture/reset_posture.json`（另有表格版 `reset_posture.csv`）。里面记录了**全身所有关节**的目标值，包括躯干、**头部**、双臂和夹爪，名字和机器人 `joint_state` 一致，单位同时给 rad 和度；另外记录了双手在这个姿态下的 EE 位姿，以及建议的到位容差。每次回放之前、以及 policy 推理之前，都把机器人 reset 到这个状态。

关键数值：

| 部位 | 关节 | rad | 度 |
|---|---|---|---|
| **头部** | head_joint_1 | 0.028172 | 1.614 |
| **头部** | head_joint_2 | 0.784750 | 44.963 |
| 躯干 | torso_joint_1..6 | 0.001409, 0.951995, −1.754768, 0.836354, −0.001405, −0.000399 | 0.08, 54.55, −100.54, 47.92, −0.08, −0.02 |
| 左臂 | left_arm_joint_1..7 | 0.7552, 0.5663, 0.1828, −1.5726, −0.6297, −1.2131, 1.9502 | 43.27, 32.45, 10.48, −90.10, −36.08, −69.51, 111.74 |
| 右臂 | right_arm_joint_1..7 | 0.6116, −0.6339, −0.2048, −1.3763, 0.6000, −1.5708, −2.1213 | 35.04, −36.32, −11.73, −78.86, 34.38, −90.00, −121.54 |

- **头部和躯干必须和这里一致**：头部相机的标定（相机位姿 = 头部连杆正运动学 × 标定的相机外参）和所有轨迹都基于这组角度。21 条示教（cup_v1、swap_v1、box_v1）录制时，头部和躯干完全相同，最大差异 1e-5 rad。
- 建议到位容差：头部和躯干 ≤ 0.005 rad（0.29°，约等于画面上 1.5 像素、桌面上 3 mm），双臂 ≤ 0.01 rad。
- 夹爪：录制时是 0（闭合）。轨迹在接近段会把左夹爪张开到第一行的开度，reset 时闭合没有问题；也可以先张开到第一行的开度。
- 这个姿态下，双手在身体两侧、桌面上方约 12 cm、比桌子近边靠后约 10 cm，不在头部相机视野内；离身体至少 6.9 cm；离关节限位至少 10°（左臂 20.5°）。
- 每个轨迹文件的**第一行就等于这个 reset 状态**。轨迹本身不包含"从任意姿态回到 reset"这一段，请先用你们自己的安全运动移到 reset，再开始执行。

## 4. 物体摆放

轨迹是**开环**的：它是按照示教时物体的位置算出来的。物体必须放在该 episode 示教时的位置：
- **每条轨迹都有两张对应的头部相机图**：
  - `placement/<task>_ep<i>_raw.jpg`：示教第一帧的原始画面，没有标注，800×500，和机器人头部相机 `left_raw` 的画面格式一致；
  - `placement/<task>_ep<i>.jpg`：同一帧加上标注。绿色轮廓是物体模型应在的位置，黄色是抓取点和接近方向，图下方写着物体在机器人 base 坐标系里的位置和朝向。
- 建议的摆放方法：机器人 reset 到第 3 节的姿态（**头部角度必须一致**，否则画面对不上），打开头部相机画面，和 `_raw.jpg` 叠加或并排对比，把物体挪到画面中完全重合的位置。
- 头部相机画面应该和参考图对齐。前提是头部角度和录制时一样（`head_joint_1/2` 见 CSV）。
- 服务器上有对比工具：拍一张当前头部画面，配上当前的 `joint_state`，工具会算出物体需要挪动多少，并给出能否直接回放的判断。

```
python -I /home/gaoyiche/HandDemo/real_rby1/scripts/placement_guide.py compare <demo_raw_ep_dir> <scene.json> <actions.npz> <rim|ring_pinch> <新图片> <新joints.npz> <输出目录>
```

如果物体放不到原位，可以用服务器上的 `scripts/replan.py` 按新位置重新生成轨迹。重新生成后必须再过一遍 `safe_traj.py` 和 `export_real.py` 的安全检查。

桌子：桌面离地 66.5 cm，桌面尺寸 1.4 × 0.6 m。轨迹按录制时的桌子位置生成，桌子挪动后请重新录制或重新生成。

### 4b. box_v1 的摆放

- `placement_guide.py` 和 `replan.py` **不支持 box_v1**，只能按参考图手动摆放：
  - `placement/box_v1_ep<i>_raw.jpg` 是原始画面；
  - `placement/box_v1_ep<i>.jpg` 是标注图。绿色是纸箱起始位置（摆在这里），蓝色是人手推完后的位置，黄色是接触点和推的方向。
- 起始位置（机器人 base 坐标系）：ep0 (0.527, 0.198) m，朝向 3.8°；ep1 (0.521, 0.197)，1.8°；ep2 (0.518, 0.199)，1.8°。纸箱的长边（30 cm）大致沿机器人的左右方向放，见参考图。
- 纸箱模型是 30 × 19 cm 底面、**17 cm 高**。用户给的尺寸是 30 × 17 × 19 cm，17 和 19 哪个是高，是按图像边缘拟合选的（17 cm 高的拟合误差更小），没有实测确认。
- 推是**开环**的：仿真里纸箱质量假设 0.4 kg、摩擦系数假设 0.4，都没有实测。真实纸箱最后停的位置可能和仿真不同。

## 5. 夹爪

**box_v1 的夹爪全程闭合**（每一行都是 `gripper_closed = 1`、开度 0），用闭合的指尖推箱子。下面的说明针对 swap_v1 和 cup_v1。

- `gripper_closed = 0` 时是张开状态，张开量见 `left_gripper_open_m`（每根手指的张开量，单位 m）。在接近、插入、停留阶段保持这个开度。
- `gripper_closed = 1` 时闭合，并一直保持到结束。仿真里用 40 N 的力夹住物体。
- **`left_gripper_finger_joint_1` 的符号还没有在真机上确认**：文件里假设"负值 = 张开"（URDF `gripper_finger_l1` 的范围是 [−0.05, 0]）。第一次执行前，请先发一个小幅张开指令确认方向。如果方向不对，请改用 `left_gripper_open_m` 或 `left_gripper_closed_norm` 来驱动夹爪。
- 闭合阶段（`phase = close`）手臂静止 0.6–1.0 s，这段时间是按 URDF 手指速度 0.05 m/s 估算的。如果真机夹爪更慢，请加长等待时间，或者等夹爪闭合到位后再继续。

## 6. EE 文件（`trajectories/ee/`）

- 内容：左臂末端位姿，即 URDF 连杆 `ee_left` 在 `base` 坐标系下的位姿，和机器人发布的 `/robot/left_end_effector_pose` 定义一致（用录制数据验证过，误差为 0）。位置单位是 m，四元数顺序为 x, y, z, w。另外包含夹爪列。
- 用途：pi05 等使用 EE 动作的模型的**训练标签**。它和关节文件描述的是同一条运动。
- **不建议直接把 EE 文件发给机器人执行**：左臂是 7 自由度，同一个 EE 位姿对应很多组关节角。仿真测试里，普通 IK 不给参考姿态时，15 条全部换到了别的关节解（和计划最多差 2.7 rad），有的加速度达到上限的 2.5 倍。如果一定要用 EE 指令执行，控制器必须同时拿关节文件作为零空间参考姿态。

## 7. 已经做过的验证

每个关节文件都**直接从 CSV 读回**，用 PCHIP 插值后在 MuJoCo 物理仿真中完整回放了一遍（`verification/VERIFICATION.txt`，视频在 `verification/videos/`）：

- 抓取任务成功：15/15。物体被抬起 6.5–26 cm，结束时仍在夹爪中。
- 推箱子成功：3/3。成功标准是纸箱最终位置和人手推完的位置相差 ≤ 3 cm、朝向相差 ≤ 10°，并且没有倒。
  - 实际结果：位置误差 1.2 / 0.2 / 1.1 cm；仿真推动的距离 18.7 / 17.3 / 23.4 cm，人手是 18.5 / 17.0 / 23.1 cm。
  - **注意，朝向没有复现**：人手推的时候纸箱转了 3.0–6.5°，仿真里基本不转（−1° 到 +2°）。10° 的朝向容差比人手转的角度还大，所以这项检查分辨不出这个差别。
  - 只有左夹爪的一根手指碰到纸箱，接触点在被推那一面（左侧面）的中间高度；纸箱最大倾斜 0.03°，没有离开桌面。
- 手臂和身体的物理接触为 0 帧；机器人和桌子的接触为 0 帧（三个任务都是）。
- 逐采样点的几何检查（关节路径加密到 0.005 rad 一步）：
  - 离身体 ≥ 3 cm，实际最小 4.46 cm；
  - 离关节限位 ≥ 5°（按 URDF 和 MuJoCo 限位的交集）；
  - 手臂在桌面以上 ≥ 5 mm。
- 速度和加速度：插值后峰值速度 ≤ URDF 上限的 25%，峰值加速度 ≤ 44%（box_v1 是 38–44%）。
- box_v1 另外检查了：接近时整条手臂离纸箱 ≥ 2.3 cm；除夹爪以外的连杆离纸箱 ≥ 7.4 cm；夹爪压进纸箱规划表面的深度 ≤ 5.7 mm（上限 7 mm）。
- 仿真中关节跟踪误差 0.007–0.020 rad（位置伺服 kp 4000 / kv 400，带速度前馈）。
- box_v1 由另一个独立的检查程序从 CSV 重算了一遍：几何检查和物理回放的结果都和上面一致。
- CSV 和 npz 完全一致；EE 列和正运动学的结果吻合到 0.001 mm。

## 8. 第一次上真机：建议的流程

1. 机器人先到初始姿态（第 3 节），确认头部和躯干角度和 CSV 一致。
2. **不放物体，先空跑**：低速运行，手放在急停上，观察接近段（从身体两侧绕到物体上方）是否离桌子、身体都有足够距离。
3. 确认夹爪方向（第 5 节）。
4. 按参考图放好物体（第 4 节），再完整运行。
5. 建议先试这几条：`swap_v1` ep2、ep4、ep3；`cup_v1` ep0、ep2；`box_v1` ep1。
6. **抓取任务结束时物体还拿在手里**：没有放下和回位的动作，结束后请手动处理。box_v1 结束时手臂停在纸箱后方 6 cm、上方 8 cm 的位置，也不会回到初始姿态。

已知的风险和局限：
- 头部相机支架不在碰撞模型里。
- 桌子近边的位置是推算的，相机看不到它。不过接近段离桌沿还有约 8 cm 余量。
- 运动中被夹住的物体只在物理仿真里检查过有没有碰到身体或桌子。
